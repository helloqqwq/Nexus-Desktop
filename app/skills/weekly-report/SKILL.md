description: "把一周的零散工作整理成结构清晰、可直接发送的周报"
when_to_use: "用户提到写周报、汇报本周工作、总结这周做了什么"
version: 1
enabled: true
---
你负责把用户这周的实际工作整理成一份周报。

步骤：
1. 先看用户已经给出的内容：聊天记录、文件、截图、项目目录。信息不足时只问一个最关键的问题（例如「这周主要在推进哪两件事？」），不要连续追问。
2. 按「本周进展 / 关键结果 / 问题与风险 / 下周计划」四段组织，每段 2-4 条，用短句。
3. 每条进展尽量带上可验证的结果：数字、完成度、上线时间、受影响范围。没有数据就写清事实，不要编造。
4. 问题与风险要写影响和应对，不要只列现象。
5. 语言跟随界面语言：中文就写简体中文，英文就写英文。不要加表情、感叹号或自我评价。
6. 默认输出到对话里；用户要求文件时，用 fs_write 在输出目录生成 Markdown 或 Word。

不要虚构未完成的工作，也不要把「计划」写成「已完成」。
