# Nexus 项目设计

## 1. 总体架构

```
┌──────────────────────────── WebView2 (HTML/CSS/JS) ────────────────────────────┐
│ 悬浮球/宠物窗口  │  对话窗口  │  设置  │  历史  │  确认弹窗  │  截图蒙层      │
└───────────────▲───────────────────────────────────────────────┬───────────────┘
                │ window.Nexus.onEvent(json)  ← 推送事件          │ pywebview.api.* 调用
┌───────────────┴───────────────────────────────────────────────▼───────────────┐
│                              Python 内核（UI 无关）                            │
│  Agent 编排  │  LLM 客户端(SSE)  │  工具注册表  │  诊断白名单  │  安全策略       │
│  配置/DPAPI  │  SQLite 历史      │  文件沙箱    │  日志审计    │  模式管理       │
└──────────────────────────────────┬────────────────────────────────────────────┘
                                   │ 同一内核
                        ┌──────────▼──────────┐
                        │ 安全 / 监管 / 全部下放 │
                        └─────────────────────┘
```

设计原则：
1. **内核零 UI 依赖**：界面层只通过 JS API 调用 `core/`，对话与工具逻辑不依赖 WebView。
2. **一切副作用可审计**：写文件、执行命令、修改系统设置全部先过 `safety.py`，并写 `audit` 表。
3. **模型是可替换的外设**：OpenAI 兼容协议，无 Key 时进入"离线诊断"策略，不阻塞核心功能。

## 2. 模块职责

| 模块 | 职责 |
| --- | --- |
| `main.py` | 启动托盘/悬浮球/主窗口；参数解析与单实例检测 |
| `core/config.py` | 读写加密配置 `config.dat`（AES-256-GCM）；API Key 额外用 DPAPI（`CryptProtectData`，ctypes）加密；环境变量 `NEXUS_API_KEY` 优先级最高 |
| `core/avatar.py` | 头像上传校验、方形裁切与 256×256 PNG 落盘 |
| `core/secret.py` | 本地数据加密：DPAPI 保护 32 字节主密钥（`secret.key`），AES-256-GCM 加密配置与历史字段 |
| `core/llm.py` | `/chat/completions` 流式请求、工具调用（tools/tool_calls）、重试与超时、取消 |
| `core/agent.py` | 系统提示词、场景预设、工具循环（最多 N 轮）、事件推送、历史落库 |
| `core/tools/registry.py` | 工具元数据（名称/描述/JSON Schema）+ 分发；统一 `{ok, data, error}` 返回 |
| `core/tools/fs_tools.py` | `fs_read / fs_write / fs_edit / fs_list / fs_search` |
| `core/tools/shell_tool.py` | `shell_run`：仅允许白名单程序 + 参数校验，超时/输出截断 |
| `core/tools/diag_tools.py` | `net_diag / proc_list / sys_info / service_list` |
| `core/tools/app_tools.py` | `app_open / screenshot_capture / todo_write` |
| `core/safety.py` | 路径沙箱、危险动作判定、确认令牌、审计写入 |
| `core/store.py` | SQLite：`sessions / messages / tool_runs / files / audit / schedules`；敏感字段逐条 AES-256-GCM 加密，旧明文数据首次启动自动迁移 |
| `web/` | 悬浮球、聊天、设置、历史、确认弹窗 |

## 3. 前端 ↔ 后端协议

### 3.1 调用（JS → Python）
```js
await window.pywebview.api.send({ text, scene, attachments: [{type:'image', data:'base64'}] })
await window.pywebview.api.stop()
await window.pywebview.api.settings_get() / settings_save({...})
await window.pywebview.api.history_list({type, limit}) / history_get(id)
await window.pywebview.api.confirm_reply({ id, allow: true })
await window.pywebview.api.win({ action: 'drag'|'hide'|'show_chat'|'open_path', x, y })
```

### 3.2 事件（Python → JS）
| type | 载荷 | 说明 |
| --- | --- | --- |
| `state` | `{status: idle/thinking/working/error}` | 驱动球体/宠物状态 |
| `assistant_delta` | `{id, text}` | 流式增量 |
| `assistant_done` | `{id, text}` | 消息完成 |
| `tool_start` | `{id, name, args}` | 显示执行卡片 |
| `tool_end` | `{id, name, ok, summary, ms}` | 折叠为结果卡片 |
| `confirm_request` | `{id, title, detail, command}` | 弹出确认框，等待 `confirm_reply` |
| `todo` | `{items:[{text,status}]}` | 任务清单渲染 |
| `files` | `{items:[{path,name,size}]}` | 生成文件卡片 |
| `error` | `{message, hint}` | 可读错误 + 建议 |

## 4. 工具清单（对齐通用 Agent 工具语义）

| 工具 | 参数要点 | 安全级别 |
| --- | --- | --- |
| `fs_read` | path, offset, limit | 低（限沙箱根目录白名单） |
| `fs_write` | path, content | 中（展示路径，写入审计） |
| `fs_edit` | path, old, new | 中（唯一匹配校验） |
| `fs_list` | dir, pattern | 低 |
| `fs_search` | pattern, dir, glob | 低 |
| `shell_run` | program, args[], timeout | 高（白名单 + 确认） |
| `net_diag` | action: ping/dns/ipconfig/route/proxy/ports/tcp | 低（只读诊断） |
| `proc_list` | sort, limit | 低 |
| `sys_info` | - | 低 |
| `service_list` | filter | 低 |
| `app_open` | path/url | 中（确认） |
| `screenshot_capture` | mode: full/region | 中（隐私提示） |
| `todo_write` | items[] | 无副作用 |

修复类动作（`ipconfig /flushdns`、`netsh winsock reset`、重启网卡/服务等）不直接暴露给模型，而是由 `safety.py` 生成"待确认动作"，用户确认后才经白名单执行。

## 5. 安全模型

1. **凭据与本地数据**：不落明文。设置整体加密为 `config.dat`，API Key 在配置内再套一层 DPAPI 密文；对话标题、消息正文、工具参数、文件路径、审计详情、定时任务均以 AES-256-GCM 加密存库；支持 `NEXUS_API_KEY` 环境变量覆盖。
2. **路径沙箱**：默认仅允许 桌面/文档/下载/Nexus 输出目录 + 用户显式添加的目录；越界需确认。
3. **命令白名单**：`ipconfig / ping / nslookup / netsh(只读子命令) / tasklist / systeminfo / sc query / netstat / getmac / route print` 等；禁止 `cmd /c`、`powershell -enc`、删除类命令。
4. **确认机制**：每个危险动作生成一次性令牌，UI 弹窗确认后 60s 内有效，执行前二次校验。
5. **审计**：所有工具调用写 `audit` 表（时间、工具、参数摘要、结果、耗时）。

## 6. 前端设计语言（模仿 DeepSeek Harness，已确认）

- **风格**：极简黑白灰 + 单点蓝色强调，浅色默认、深色可切；细描边、低阴影、克制圆角，信息密度以"对话优先"。
- **字体**：拉丁 `Montserrat`（缺失时 Segoe UI），中文 `"PingFang SC", "Microsoft YaHei UI"`；等宽 `"JetBrains Mono", Consolas`；正文 14px/22px，标题 16px/24px，辅助 12px/18px。
- **设计令牌**（取自 DSH 主题包，浅色 → 深色）：
  - 背景 `#FFFFFF → #151517`；层 1 `#F9FAFB → #232324`；层 2 `#F1F3F5 → #2C2C2E`
  - 描边 `rgba(0,0,0,.04/.10/.12/.16) → rgba(255,255,255,.06/.12/.16/.20)`
  - 文字 `#0F1115 → #F9FAFB`；次级 `#61666B → #CFD3D6`；辅助 `#ADB2B8 → #80858C`
  - 主按钮 `#0F1115`（深色下 `#F9FAFB` 反色）；强调蓝 `#4176E6`；成功 `#22C55E`；警告 `#F59E0B`；错误 `#EF4444`
  - 圆角 `4 / 8 / 12 / 16 / 20 / 28`（xs→panel）；面板用 16，卡片 12，按钮 8，输入框 12
- **布局**：左侧 280px 侧栏（可折叠，含新对话、导航、会话列表、模式切换）+ 主对话列（最大宽 840px 居中）；顶部会话标题条；底部 composer 为圆角 16 的描边容器，模型/推理/语音/截图与发送按钮同排；右侧 70vw 预览面板（左预览、右 260px 文件树，仅产出文件时展开，窗口窄于 1240px 改为覆盖式）。
- **悬浮球**：白色玻璃球 + 黑色描边环 + 蓝色状态点，呼吸光环；hover 放大 1.05；拖拽半透明；贴边收成半圆。宠物形态为黑白线条小精灵，蓝点作眼睛高光。
- **宠物形态**：内联 SVG 小精灵，眨眼/摆尾，四种状态（空闲、思考、执行、报错）对应动画与气泡提示；与球体一键切换。
- **主窗口**：460×700 无边框圆角面板（可最大化，最大化不遮挡任务栏）；顶部为拖拽区 + 模式徽标；消息区；底部输入框（Enter 发送，Shift+Enter 换行，附件/截图/语音按钮）。
- **工具卡片**：一行摘要 + 状态点，点击展开参数与输出（等宽字体，限高滚动）。
- **确认弹窗**：居中卡片，红色描边表示危险，按钮"取消 / 允许执行"，附命令原文。
- **设置**：分组卡片（模型连接、输出目录、外观与启动、模式），保存即生效。
- **历史**：左侧类型切换（对话 / 文件 / 排查），右侧时间线。
- **动效**：消息 180ms 上滑淡入；流式打字光标；球体状态切换 240ms；尊重 `prefers-reduced-motion`。

### 6.1 语音、截图与右侧面板（本轮定稿）

- **语音输入**：本地 `sherpa-onnx` + SenseVoice-Small int8，模型约 228MB，存放 `%APPDATA%\Nexus\models\`；首次使用从 hf-mirror 下载，GitHub 作为回退，不依赖 Windows 语音功能。`Ctrl+Alt+V` 或麦克风按钮切换录音，识别文本插入输入框。
- **区域截图**：自绘 Tk 全屏遮罩 + `GetCursorPos`/`ClientToScreen` 物理坐标映射，视觉选框与最终裁剪区域同源，不调用系统截图工具。
- **提问交互**：`ask_request` 在对话消息列内联渲染卡片（选项、文本输入、跳过），不使用全屏遮罩，用户可同时操作其他区域。
- **右侧面板**：宽度约 70vw，内部左预览、右 260px 文件树；仅在模型产出文件（`files` 事件）时自动展开，普通对话不打扰。

## 7. 运行模式

运行模式统一为三级权限，原在线/专业模式已合并：

- 安全：只保留读取类工具，隐藏写文件、删除、命令执行、程序启动、UI 操作与定时任务。
- 监管：全部工具可用；执行命令、运行程序、修改系统和 UI 操作前弹出确认，写入文件不确认。
- 全部下放：全部工具可用，跳过逐条确认，由用户承担全部责任。

- 三种模式共享配置与数据库，可在设置页或悬浮球菜单切换；旧配置的 `online` / `pro` 自动迁移为 `supervised`。
- 定时任务在监管模式下无法使用需要确认的工具；全部下放模式下按当前权限自主执行。

## 8. 打包与发布

- `build\build_release.py`：调用 PyInstaller 构建启动器 EXE，再把 `app` 编译成 `.pyc` 放到外部 `lib\app\`（删除 `.py`），最后调用 NSIS 生成安装包并压缩绿色包。
- 分体式结构：`Nexus.exe` 只做入口；依赖库在 `_internal\`；Nexus 业务字节码在 `lib\app\`，不在 EXE 的 PYZ 中。
- 安装包：NSIS Unicode，中英双语，可自选安装位置，默认 `%LOCALAPPDATA%\Programs\Nexus`，无需管理员权限。
- 绿色便携：`Nexus-Portable-<版本>` 内放 `portable.flag`，数据写到同目录 `data\`。
