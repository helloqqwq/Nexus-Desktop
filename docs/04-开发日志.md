## 2026-11-13（定时任务改为 AI 自提示延时任务）

### 1. 反馈

- 原来的定时任务理解错了：它不该是“每隔 N 分钟静默跑一次、只弹通知”，而应该是 AI 给自己留一条延时消息。
- 例如“5 分钟后帮我写一个 HTML 网页”：AI 先设计好一段自包含提示词存起来，5 分钟到点后把这段提示词当作一条消息发给自己，像用户刚说完一样开始执行。

### 2. 改动

- `schedule_task` 增加 `delay_minutes`（一次性延时）并保留 `interval_minutes`（周期重复）；工具描述明确要求 prompt 自包含、是给自己的指令而不是给用户的提醒文案。
- `schedules` 表新增 `once`、`session_id`；旧库启动时自动 `ALTER TABLE` 补齐。
- `Scheduler` 增加 `runner` 回调与 `context_session_id`：到点优先交给应用层执行，一次性任务执行后写 `last_result` 并禁用，周期任务按间隔排下一次。
- `NexusApp.run_scheduled_task`：新建「定时 · 标题」会话 → 推 `schedule_start` → 把 prompt 作为用户消息交给 Agent → 每个事件补 `session_id` 后推送 → `run_end` + `schedule_done`。
- 前端 `onEvent` 按 `session_id` 过滤流式事件；收到 `schedule_start` 自动切到对话页并打开该会话，`schedule_done` 刷新侧栏；历史页「定时任务」区分一次性/周期，已执行的一次性任务显示「已完成 · 执行于 …」，不再显示启停按钮。

### 3. 验证

- 真实模型链路：插入一条 60 秒后到期的一次性任务 → 到点自动新建会话「定时 · 自检：一次性延时任务」→ user 消息为写入的 prompt → assistant 回复“定时任务已执行。”→ 任务 `enabled=0` 且 `last_result` 落库；前端自动切到该会话并显示 2 条消息。
- 前端事件：模拟 `schedule_start` / `schedule_done` 均为提示 toast + 切页 + 打开会话；历史页一次性任务与已完成任务的文案正确。
- 自检 50/50 PASS。

## 2026-11-13（Office 文件预览/编辑 + 模型办公工具）

### 1. 需求与边界

- 右侧栏要能看 PDF / Word / Excel / PPT，并能在应用内编辑。
- 模型要能生成与编辑 Word / Excel / PPT；PPT 采用「先写 HTML，再逐页转 PPT」。
- 明确边界：Word / PPT 做文本级编辑，保留原格式；不做会丢失版式的整篇富文本往返。
- 环境没有 Office / LibreOffice，PPT 不能用 COM 或 soffice 渲染，全部自己解析。

### 2. 预览实现

- PDF：PyMuPDF 逐页渲染成 PNG，`pdf_page` 按需取页，前端翻页 + 0.6–3.0 缩放，不一次性塞入整份文件。
- Word：python-docx 按 body 顺序遍历段落与表格，转成带样式的 HTML（标题层级、对齐、加粗/斜体/下划线/颜色/字号、图片 data URL、表格）。编辑态按段落 contenteditable 改文字，保存只写回段落文本，`_apply_text` 保留首个 run 的格式。
- Excel：openpyxl 读网格（值 + 缓存值 + 公式 + 粗斜体/颜色/背景/对齐/列宽），前端画带行列表头、工作表标签的表格，单元格 contenteditable。保存不走 openpyxl 重写，而是解压 xlsx 直接改 `xl/worksheets/sheetN.xml`（字符串用 inlineStr、数字写 `<v>`、公式写 `<f>` 并设置 `fullCalcOnLoad`），图表/图片/条件格式原样保留。
- PPT：python-pptx 把每页形状按 EMU 换算成百分比坐标，前端用绝对定位 + `cqw` 字号还原；支持文本框（按段落/run 的粗斜体、颜色、字号、对齐、垂直锚点）、图片、表格、图表占位、形状填充/描边。编辑态直接点文本框改字，保存按 `slide+shape` 写回，保留首个 run 的字体。
- 统一交互：Markdown / Word / PPT 共用预览头右侧「渲染 / 编辑」分段控件；Excel 没有渲染态，改单元格即标记未保存。切换文件、切回渲染、关闭面板都会自动保存未落盘的修改，Ctrl+S 也可保存。

### 3. 模型工具

- `office_read`：PDF 按页取文本、Word 段落+表格、Excel 二维表、PPT 每页文字，均带截断标记。
- `docx_write` / `xlsx_write` / `pptx_write`：结构化生成。PPT 为 16:9 原生对象，内置封面/章节/内容/表格/结尾版式，带页码与页脚。
- `html_to_pptx`：按 `section.slide`（或 `.slide` / `[data-slide]`）切页，提取 h1/h2、li、p、table、img；解析 `<style>` 的 background/color/accent，背景与文字色会带进 PPT；图片限制在 HTML 目录内；生成的是可继续编辑的文本/表格/图片，不是整页截图。
- `office_edit`：`docx_text` / `xlsx_cell` / `pptx_text` / `pptx_append`，用于模型对已有文件做小改动。
- 写类办公工具全部加入安全模式排除；`office_read` 保持只读可用。
- 系统提示词补充办公工具和 HTML→PPT 的写法要求；工具返回 `files` 事件，右侧栏自动刷新并展示新文件。

### 4. 踩坑

- `xlsx` 保存最初用 `shutil.move`，而 zip 句柄还没关闭，Windows 报 WinError 32；改为读完所有条目后关闭 zip，写临时文件再 `os.replace`。

- HTML 转 PPT 图片若允许任意相对路径会越界读取，限制在 HTML 所在目录内。

- 踩坑 3：NSIS 报 `Bad text encoding`，Unicode 脚本必须保存为 UTF-8 with BOM；构建脚本已自动补 BOM。
- 踩坑 4：`SendMessage ... "STR:...$\r$\n..."` 会在编译期被拆成多个参数；改为先 `StrCpy $R0`，再传 `"STR:$R0"`。

### 8. 托盘退出后进程残留（同日追加）

现象：托盘菜单点击“退出 Nexus”后，界面消失但任务管理器仍有进程。

根因：
- `quit()` 只销毁 `orb` 和 `main`，漏掉 `quick` 快捷输入窗；pywebview 的主循环仍在运行，进程不退出。

- 退出时依次销毁 `quick`、`orb`、`main`，让 pywebview 主循环结束。
- 托盘停止移到独立 daemon 线程，避免阻塞退出流程。
- 增加 2.5 秒 `os._exit(0)` 兜底，防止 WebView2/托盘线程卡住导致残留。
- 实测：通过同一 `quit()` 路径触发退出，1.44 秒内进程完全消失。
