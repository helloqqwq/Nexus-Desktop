# Nexus 项目总文档

> 版本：0.1.0  
> 日期：2026-11-09  
> 状态：P0-P5 功能完成；本地数据已加密，分体式绿色包与 NSIS 安装包已构建并完成安装/卸载实测。

## 1. 项目定位

Nexus 是一个面向普通 Windows 用户的本地优先桌面 AI 助手。它不要求用户懂命令行，目标是让用户用大白话完成三类事：

1. **电脑管家**：查网络、查卡顿、查系统信息、修常见网络问题。
2. **知识助手**：写文档、做单文件网页、整理文件、看截图回答问题。
3. **电脑操作**：通过 Windows UI 树替用户点按钮、填输入框、打开常用程序。

设计原则：

- 绿色免安装，双击即用，不依赖用户预装 Python。
- 本地优先，历史与文件都在本机，只有对话内容会按需发送给模型服务。
- 危险动作必须用户确认，密钥不落明文。
- 提供安全 / 监管 / 全部下放三级运行权限，原在线/专业模式已合并。

### 一次对话的数据流

1. 前端 `NexusApi.send({text, attachments, session_id})`。
2. `NexusApp.start_run` 创建会话、启动后台线程，避免阻塞 UI。
3. `Agent.run` 组装系统提示词 + 最近历史 + 附件，调用 `LLMClient.chat`。
4. 模型流式返回文本增量，Agent 推送 `assistant_delta`。
5. 若模型返回工具调用，Agent 逐个执行：
   - 需要确认的工具走 `Safety.issue_confirm`，前端弹确认框，`NexusApi.confirm_reply` 回传。
   - 执行结果作为 `tool` 消息回给模型，继续下一轮。
6. 结束后推送 `assistant_done`、`run_end`，消息/工具/文件落库。

## 5. 数据模型

数据库：`%APPDATA%\Nexus\nexus.db`（WAL）。敏感字段以 `enc:v1:<base64>` 形式存储，使用 AES-256-GCM 加密；旧版本明文记录在首次启动时原地加密并 `VACUUM` 重写。

| 表 | 关键字段 | 用途 | 加密字段 |
| --- | --- | --- | --- |
| `sessions` | id, title, mode, created_at, updated_at | 对话会话 | title |
| `messages` | id, session_id, role, content, meta, created_at | 对话消息（含工具调用名） | content, meta |
| `tool_runs` | id, session_id, tool, args, ok, summary, ms, created_at | 工具执行记录 | args, summary |
| `files` | id, session_id, path, name, size, created_at | 生成/截图文件 | path, name |
| `audit` | id, ts, action, detail, ok | 安全审计流水 | detail |
| `schedules` | id, title, prompt, interval_minutes, next_run, enabled, last_run, last_result, created_at, once, session_id | 定时任务（`once=1` 为一次性延时任务） | title, prompt, last_result |
| `meta` | key, value | 迁移标记（crypto_version） | — |

配置：`%APPDATA%\Nexus\config.dat`（AES-256-GCM 整文件加密）。每个厂商的 API Key 单独用 DPAPI 加密后存放在 `llm.providers.<id>.key`，形如 `dpapi:<base64>`；`llm.provider` / `llm.model` 记录当前选择。旧版的单一 `llm.api_key` 首次启动会自动迁移为 DeepSeek 厂商配置。主密钥保存在 `secret.key`，只存 DPAPI 密文，绑定当前 Windows 账户与电脑。

## 7. 安全模型

### 7.1 路径沙箱

- 写：桌面、文档、下载、图片、输出目录、用户手动添加的 `extra_dirs`。
- 读：用户主目录、Nexus 数据目录、`extra_dirs`。
- 拒绝读取：`.ssh`、`id_rsa`、`id_ed25519`、Cookies、Login Data、Web Data、Local State、Microsoft Credentials、Microsoft Protect、NTUSER.DAT。
- 所有路径先 `expandvars/expanduser/resolve`，再做 `relative_to` 判断，防止 `..` 逃逸。

### 7.2 命令执行

- 程序白名单：ping、nslookup、tracert、ipconfig、netstat、route、arp、getmac、tasklist、systeminfo、sc、netsh、whoami、hostname。
- 参数逐项正则全匹配，限制参数个数。
- 禁止词：reset/renew/release/stop/start/delete/remove/kill/taskkill/shutdown/format/reg/sc config/netsh advfirewall 等。
- `netsh` 只允许 `wlan show`、`interface show`、`winsock show`、`winhttp show` 等查看类子命令。
- 使用 `subprocess.run(list)`，不经过 shell，避免拼接注入。

### 7.3 确认机制

- `Safety.issue_confirm(action, detail, payload, ttl=60)` 生成一次性 token。
- 前端收到 `confirm_request` 后弹框；`NexusApi.confirm_reply` 回传 allow。
- `NexusApp._confirm` 最多等待 120 秒；超时按拒绝处理。
- 一次确认只消费一次，不能重放。

### 7.4 UI 自动化

- 拒绝操作：UAC/consent.exe、LogonUI、winlogon、csrss、lsass、services、SecurityHealthService、SmartScreen、Windows 安全中心、凭据管理器、安全桌面、Nexus 自身窗口。
- 只允许同一完整性级别窗口；管理员程序需要 Nexus 也以管理员运行。
- `ui_act` 每次都需要确认；支持动作限定为 click/double_click/right_click/focus/invoke/set_text/send_keys。
- `send_keys` 不提供 Win、Alt+F4 等危险组合。

### 7.5 密钥与隐私

- 每个厂商的 API Key 用 DPAPI + 固定 entropy 单独加密后保存，读取时解密。
- 环境变量 `NEXUS_API_KEY` 可临时覆盖当前厂商的 Key。
- 不在日志、文档、代码中输出密钥；`get_state` 只返回「是否已配置」。
- 截图、对话、工具结果会上传至所配置的模型服务；本地历史为明文 SQLite。

### 7.6 运行时权限模式

- `mode=safe`：只暴露读取类工具，隐藏 `fs_write`、`fs_edit`、`fs_delete`、`shell_run`、`shell_exec`、`app_open`、`app_launch`、`ui_act`、`schedule_task`、`cancel_schedule`。
- `mode=supervised`：全部工具可用；命令执行、打开/运行程序、系统修改、删除与 UI 操作逐条确认，`fs_write` / `fs_edit` 不确认。
- `mode=full`：全部工具可用，跳过逐条确认，由用户承担全部责任；子进程仍会移除 `NEXUS_API_KEY` 环境变量。
- 旧配置的 `online` / `pro` 在加载时自动迁移为 `supervised`。
- 命令执行可取消：停止按钮设置取消事件，`_run_process` 轮询并终止子进程。

### 7.7 联网搜索/抓取

- 使用 DeepSeek Search/Fetch API，优先取 DeepSeek 厂商的 Key（即使当前对话使用其他厂商），按官方价格计费。
- `web_fetch` 只接受 http/https，拒绝带用户名密码的 URL、localhost、127.0.0.1、::1、*.local。
- 正文截断 12000 字；工具结果标注为资料，系统提示要求不执行网页内的指令。

### 7.8 定时任务

- 语义：AI 给自己留一条延时消息。工具的 `prompt` 必须自包含，到点后原样作为一条用户消息交给 Agent，而不是发给用户的提醒文案。
- 一次性任务用 `delay_minutes`（1 分钟–7 天），重复任务用 `interval_minutes`；两者都有上限校验，`once` 与创建时的 `session_id` 一起入库。
- 创建任务需要确认；运行无人值守，`confirm=None`，需要确认的工具自动返回“用户取消”。
- 调度线程每 30 秒检查到期任务，串行执行。执行时新建「定时 · 标题」会话，先推 `schedule_start`，随后带 `session_id` 的流式事件、`run_end`、`schedule_done` 依次推给界面，前端自动切到该会话展示全过程。
- 一次性任务执行后写 `last_run` / `last_result` 并自动禁用；重复任务按间隔排下一次。历史页「定时任务」分页显示状态、提示词与结果。

### 7.9 多厂商模型与设置分页

- 内置 8 家：小米 MiMo、火山方舟、DeepSeek、硅基流动、Kimi、智谱 GLM、MiniMax、通义千问；第 9 格为自定义。
- 设置页与引导页都用 3×3 厂商网格；点击卡片展开 Key、接口地址、可用模型、测试连接与「设为当前」。
- 每家厂商的 Key 独立保存，可同时配置多家；主界面模型菜单按厂商分组，只列出已配置厂商的模型，选择后写回 `llm.provider` / `llm.model`。
- 自定义支持两种协议：OpenAI 兼容（`{base}/chat/completions`）与 Anthropic 兼容（`{base}/v1/messages`）；两种协议都支持流式文本、思考内容与工具调用。
- 「刷新可用模型」直接读取厂商 `GET /models`，返回结果可按需勾选/删除后保存。

### 7.10 自动更新与下载托管

- 更新源优先级：`update.base_url` 下的 `update.json` → GitHub Releases（`update.repo`）。
- 清单字段：`version`、`notes`、`installer.name/url/size/sha256`，可选 `simulate`；`simulate: true` 表示只下载并校验，不执行安装。
